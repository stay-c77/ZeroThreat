[App Launch]

2) CLICK-SCAN PIPELINE (DEFAULT BROWSER INTENT)
======================================================================

[External app click -> ACTION_VIEW http/https]
  |
  v
SafeBrowserActivity.onCreate
  |
  +--> extract intent.dataString
  +--> handleUrl(rawUrl)

handleUrl(rawUrl)
  |
  +--> normalize URL to https://...
  +--> parse domain
  |
  +--> if domain invalid ------------------------------> openInExternalBrowser + finish
  |
  +--> normalizeBlockedUrl + isUrlBlocked?
  |       |
  |       +--> yes -----------------------------------> toast "This URL is blocked" + finish
  |
  +--> smartModeEnabled?
  |       |
  |       +--> no ------------------------------------> openInExternalBrowser + finish
  |
  +--> source package allowed for onClick?
  |       |
  |       +--> no ------------------------------------> openInExternalBrowser + finish
  |
  +--> DNS check (DnsChecker.checkUrlExists)
          |
          +--> exists = false -------------------------> log scan as SUSPICIOUS (dns score)
          |                                             UI state = DnsFailed
          |                                             user can Continue / Block / Exit
          |
          +--> exists = true --------------------------> PhishingDetector.analyzeDetailed
                                                        + log scan
                                                        + UI state:
                                                          - SAFE       -> safe dialog
                                                          - SUSPICIOUS -> threat dialog
                                                          - PHISHING   -> threat dialog

Threat dialog actions:
  - Continue -> showBrowserChoiceDialog -> launchInSelectedBrowser
  - Block    -> blockUrlAndFinish -> UrlRepository.blockUrl -> blocked_URLs
  - Exit     -> finish

Safe dialog actions:
  - Continue -> showBrowserChoiceDialog -> launchInSelectedBrowser
  - Exit     -> finish

3) NOTIFICATION-SCAN PIPELINE (BACKGROUND SERVICE)
======================================================================

NotificationListener.onNotificationPosted(sbn)
  |
  +--> requires appPreferences.notificationMonitoring = true
  +--> package must be in enabled monitored set
      (WhatsApp, Instagram, Gmail, Telegram, Messages variants)
  |
  +--> extract text from notification extras recursively
  +--> regex URL detection + email-token guard
  +--> normalize URL candidate
  +--> skip duplicates:
      - per-notification seenLinks set
      - 5-second processedLinks cache
  |
  +--> DNS check
          |
          +--> DNS fail -> log SUSPICIOUS + showThreatNotification(reason="Non-existent domain")
          |
          +--> DNS ok -> PhishingDetector.analyzeDetailed
                        -> log scan
                        -> if per-app notification toggle enabled:
                             showEnhancedThreatNotification

Notification actions via NotificationActionReceiver:
  - ACTION_ALLOW_DOMAIN  -> UserAllowlistManager.allow(domain)
  - ACTION_SHOW_LINK     -> toast link only
  - ACTION_BLOCK_URL     -> UrlRepository.blockUrl(..., source="notification")
  - ACTION_CONTINUE_URL  -> launch ACTION_VIEW intent
  - ACTION_SHOW_IN_CHAT  -> dismiss notification

5) DETECTOR DECISION FLOW (PhishingDetector)
======================================================================

analyzeDetailedInternal(input, source, depth)
  |
  +--> parseInput(host/path/query/scheme/userInfo/redirect targets)
  |
  +--> repeated redirect key?
  |      +--> yes -> SUSPICIOUS 35 (redirect loop)
  |
  +--> unsupported scheme?
  |      +--> javascript/data/file -> PHISHING 100
  |      +--> other non-http(s)    -> SUSPICIOUS 40
  |
  +--> blank host?
  |      +--> SUSPICIOUS RiskScorePolicy.INVALID_URL (18)
  |
  +--> PDF resource?
  |      +--> SAFE 0 (scan skipped)
  |
  +--> BlacklistManager exact match?
  |      +--> PHISHING 100 (Known unsafe link)
  |
  +--> redirect chain evaluation (max depth 2)
  |      +--> unsafe redirect target -> PHISHING 100
  |      +--> suspicious target      -> SUSPICIOUS >=45
  |
  +--> UserAllowlistManager.isAllowed?
  |      +--> SAFE 0
  |
  +--> isSystemDomain?
  |      +--> SAFE 0 (ignored internal link)
  |
  +--> WhitelistManager.isWhitelisted OR static allowlist?
         +--> SAFE 0

Else heuristic scoring:
  - brand similarity / typo similarity
  - whitelist-brand similarity
  - homograph/confusable chars
  - risky keywords in host/path/query
  - suspicious TLD
  - IP literal host
  - userInfo abuse
  - shortener usage
  - redirect indicators
  - lexical features (length, dots, special-char count/density, non-HTTPS, script endpoint, random token)

Raw score -> RiskScorePolicy.normalizeHeuristicScore(raw, signalCount, critical)
  - bounded raw: 0..180
  - logistic calibration
  - boosts/floors by critical signal and signal count
  - final normalized score: 0..100

Final classification:
  - normalized >= 80 AND phishingSignalCount >= 2 -> PHISHING
  - normalized >= 10                              -> SUSPICIOUS
  - otherwise                                     -> SAFE

Output:
  AnalysisReport(result, score, description, exactBlacklistMatch)


======================================================================
6) DNS RISK SCORES (DnsChecker + RiskScorePolicy)
======================================================================

DnsChecker.checkUrlExists(url)
  - invalid URL format      -> exists=false, score=18, INVALID_URL
  - unknown host            -> exists=false, score=22, DOMAIN_NOT_FOUND
  - lookup exception        -> exists=false, score=30, LOOKUP_ERROR
  - success                 -> exists=true,  score=0

7) DATA PERSISTENCE (ROOM)
======================================================================

Database: zerothreat_database
Entities:
  - all_scanned_URLs            (AllScannedUrl, unique url)
  - detected_as_safe_urls       (SafeUrl)
  - detected_as_suspicious_URLs (SuspiciousUrl)
  - detected_as_phishing_URLs   (PhishingUrl)
  - blocked_URLs                (BlockedUrl, unique url)

UrlRepository.logScan(...)
  1) remove same URL from per-result tables
  2) upsert into all_scanned_URLs (preserve existing ID when possible)
  3) insert into one result table (SAFE/SUSPICIOUS/PHISHING)
  4) compact all_scanned_URLs IDs if gaps exist

UrlRepository.blockUrl(...)
  - inserts into blocked_URLs
